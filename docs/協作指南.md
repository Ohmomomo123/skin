## 一、事前準備

### 1. 安裝 Git

- 下載：<https://git-scm.com/download/win>
- 安裝完成後，在 PowerShell 或「命令提示字元」輸入確認：

```powershell
git --version
```

### 2. 設定 Git 身分（每台電腦只需做一次）

```powershell
git config --global user.name "你的名字"
git config --global user.email "你的Email@example.com"
```

Email 建議使用 GitHub 帳號綁定的信箱。

### 3. 取得 GitHub 存取權限

本儲存庫為 **Private（私人）**，請先請專案管理員：

1. 登入 GitHub → 進入 `Ohmomomo123/skin`
2. 點 **Settings** → **Collaborators**（或 **Manage access**）
3. 按 **Add people**，輸入對方的 GitHub 帳號並送出邀請
4. 對方到信箱或 GitHub 通知 **接受邀請** 後，才有權限 clone / push

### 4. 登入 GitHub（推送時需要）

推送私人 repo 時，Git 會要求驗證。建議使用 **Personal Access Token（PAT）**：

1. GitHub 右上角頭像 → **Settings**
2. 左側最下方 **Developer settings** → **Personal access tokens** → **Tokens (classic)**
3. **Generate new token (classic)**，勾選 `repo` 權限
4. 產生後**複製保存**（只會顯示一次）
5. `git push` 時：
   - 使用者名稱：你的 GitHub 帳號
   - 密碼：貼上 **Token**（不是 GitHub 登入密碼）

也可安裝 [GitHub Desktop](https://desktop.github.com/)，用圖形介面登入，較不需手動輸入 Token。

## 三、日常開發流程

建議每次改程式前，先更新到最新版：

```powershell
cd C:\路徑\到\skin
git pull
```

### 1. 修改檔案

常見會改的檔案：

| 檔案 | 說明 |
|------|------|
| `app.py` | 後端邏輯、標籤白話對照、API |
| `templates/index.html` | 前端介面 |
| `README.md` | 專案說明 |
| `docs/協作指南.md` | 本文件 |

### 2. 查看改了什麼

```powershell
git status
git diff
```

### 3. 加入暫存並提交（commit）

```powershell
git add .
git commit -m "簡短說明你做了什麼，例如：調整結果頁面配色"
```

**commit 訊息建議**：

- 用中文或英文皆可，但要讓其他人看得懂
- 一句話說清楚「為什麼改」或「改了什麼」
- 範例：`新增乾癬的白話說明`、`修正上傳圖片後畫面不更新的問題`

### 4. 推送到 GitHub（push）

```powershell
git push
```

若為第一次 push 新分支，可能需：

```powershell
git push -u origin main
```

### 5. 到 GitHub 網頁確認

開啟 <https://github.com/Ohmomomo123/skin>，重新整理後應能看到剛才的 commit。

## 四、多人同時修改時（避免衝突）

若 `git push` 失敗並提示類似 `rejected` 或 `non-fast-forward`，代表遠端已有別人先推送，請先拉再推：

```powershell
git pull
# 若出現衝突，見下方「五、處理衝突」
git push
```

**建議習慣**：

- 開始工作前：`git pull`
- 結束工作前：`git add` → `git commit` → `git push`
- 不要長時間只改本機、很久才 push

---

## 五、處理衝突（merge conflict）

當兩人改了同一檔案的同一區塊，`git pull` 可能出現衝突。檔案中會出現：

```
<<<<<<< HEAD
你的內容
=======
別人的內容
>>>>>>> origin/main
```

**處理步驟**：

1. 用文字編輯器打開該檔案
2. 與同事溝通，決定要保留哪段（或合併兩者）
3. 刪除 `<<<<<<<`、`=======`、`>>>>>>>` 這些標記行
4. 存檔後執行：

```powershell
git add .
git commit -m "解決與某某的合併衝突"
git push
```

不確定時，請聯絡專案管理員，**不要**使用 `git push --force` 覆蓋遠端（除非管理員明確要求）。

## 六、不要上傳到 GitHub 的東西

以下已由 `.gitignore` 排除，請勿強制加入：

- Python 快取：`__pycache__/`、`*.pyc`
- 虛擬環境：`.venv/`、`venv/`
- 環境變數檔：`.env`（可能含密碼、API 金鑰）
- 日誌：`*.log`

**AI 模型權重**也不應放進 repo（體積大），執行 `python app.py` 會自動下載到本機快取。

若不小心 `git add` 了敏感檔案，在 commit 前：

```powershell
git reset HEAD 檔名
```

## 七、分支（進階，可選）

若希望「先在自己分支改，通過後再合進 main」：

```powershell
# 建立並切換到新分支
git checkout -b feature/你的功能名稱

# 修改、commit 後推送分支
git push -u origin feature/你的功能名稱
```

再到 GitHub 網頁建立 **Pull Request（PR）**，請管理員或同事 **Review** 後合併到 `main`。

小團隊若只有 1～2 人，也可直接在 `main` 分支修改（本專案目前採此方式）。

| 指令 | 用途 |
|------|------|
| `git clone <網址>` | 第一次下載專案 |
| `git pull` | 拉取遠端最新版 |
